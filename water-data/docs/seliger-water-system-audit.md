## Метод (что считается доказательством)

Шесть слоёв **не смешиваются**:

1. **Членство relation** — way/relation listed as member + role.
2. **OSM-топология** — общие `node id` и/или общие рёбра (неупорядоченные пары соседних `nd`).
3. **Геометрия** — расстояние / touch / intersection shapely nearest_points к восстановленным полигонам 399081 (WGS84 → геодезическое расстояние pyproj).
4. **Физическая водная связь** — только если есть (2) по воде: `natural=water` или `waterway=river|stream|canal` (цепочка BFS). Близость **не** равна связи.
5. **Гидравлика через сооружение** — только если на объекте есть картографические теги сооружения (`lock`, `sluice`, `waterway=dam`, …). Канал без таких тегов — открытый waterway, не доказанный шлюз.
6. **Навигация** — **не оценивалась**.

`waterway=ditch|drain` в BFS открытой воды **не** включались (отдельный слабый класс).

Окно каталога Overpass: **56.90–57.72 N, 32.45–33.60 E** (шире прежнего 57.02–57.55 / 32.68–33.36). Источники: OSM API `/full` + Overpass. Даты выгрузки: 2026-09-07 (дамп 399081) и 2026-09-09 (граф соседей).

Порог **PORTAGE_CANDIDATE**: водная площадь, нет OSM-пути по воде, геометрический зазор **0 < d ≤ 100 m**. Интервал 100–250 m — только «рядом», не волок.

Если узлов объекта в выгрузке нет — **UNCERTAIN**, а не «нет связи».
