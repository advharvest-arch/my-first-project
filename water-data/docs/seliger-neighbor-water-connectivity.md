# Соседние водные объекты Селигера: связь по OSM vs близость

Исследование исходных OSM-данных вокруг relation **399081** (Селигер).
Код проекта, база данных и WRG не изменялись. Выводов о схеме Water DB нет.

Доказательство физической связи — только:

- одинаковые `node id`;
- общие рёбра (соседние пары `nd` в way);
- членство way в relation и роль (`outer` / `inner` / `main_stream`).

Не доказательство: название, расстояние, район, визуальная близость, KNN, `ST_DWithin`.

Расстояние ниже — только характеристика близости (минимум между вершинами внешнего контура соседа и внешнего контура Селигера).

Источник: OSM API `relation/*/full` и Overpass `out body geom` в окне 32.68–33.36 E, 57.02–57.55 N.
Селигер: 115 outer ways → 2 кольца (юг / север), 9994 уникальных узла внешнего контура.

Визуализация: [seliger-neighbor-water-connectivity.geojson](seliger-neighbor-water-connectivity.geojson).

## Б. Водные объекты, физически соединённые с Селигером

Связь подтверждается общими `node id` и (где есть) общими рёбрами. Полоновка — контрольный пример из предыдущей проверки.

### Б1. Контроль: Полоновка

```
северная площадь Селигера
  relation 399081, outer way 25826420
        ↓ общие node 365264662, 365264664, 365264663
        ↓ общие рёбра (365264662—365264664), (365264664—365264663)
Полоновка (площадь)
  relation 1203668, outer way 32487905
        ↓ общие node 365270429, 365264682, 365270430
        ↓ общие рёбра (365264682—365270429), (365264682—365270430)
южная площадь Селигера
  relation 399081, outer way 49215822
```

Параллельно осевая линия:

```
way 25826420 / node 365264664 (33.0081129, 57.3620035)
        ↓
way 32487402 (waterway=river, 52 nd, не член 399081 и не член 1203668)
        ↓
way 49215822 / node 365264682 (33.0701500, 57.3322584)
```

У реки общих **рёбер** с берегом Селигера нет: стык только концевыми узлами.

### Б2. Новый пример: relation 17001378 (устьевой полигон на севере)

Безымянный `multipolygon`, `natural=water`, `water=river`. Не член 399081, но **один из его outer ways целиком совпадает с outer Селигера**.

```
северная площадь Селигера
  relation 399081, роль outer, way 1238091260
  nd: 950124294 → 9235426556 → 11500497926
        ↓ те же 3 node (все)
        ↓ те же 2 ребра
relation 17001378
  outer way 1238091260  (общий с Селигером)
  outer way 1238091261  (второй берег, не член 399081)
        ↓ замкнутое кольцо из двух ways
        (оба конца: 950124294 и 11500497926)
водная площадь устья
```

Координаты общих узлов:

| node | lon, lat | на Селигере | на 17001378 |
|------|----------|-------------|-------------|
| 950124294 | 33.0092007, 57.5193123 | way 1238091260 | оба outer |
| 9235426556 | 33.0093517, 57.5190929 | way 1238091260 | way 1238091260 |
| 11500497926 | 33.0088573, 57.5190310 | way 1238091260 | оба outer |

Сюда же примыкает `waterway=stream` way **1238091262** (14 узлов), последний `nd` = **9235426556** — тот же узел берега Селигера. Это осевая линия того же устья, не отдельное доказательство: площадь уже стыкуется общим way.

### Б3. Ещё цепочки площадь → протока → другая площадь

Не нужны для минимума «хотя бы один», но показывают тот же критерий на именованных объектах.

**Княжа → Серемо**

```
юг Селигера, outer way 49215822
  node 220277673 (33.1775764, 57.2982325)
  node 952396939 (33.1780277, 57.2979706)
  node 952397004 (33.1773347, 57.2982987)
        ↓ 3 node, 2 ребра (220277673—952396939), (220277673—952397004)
way 81753515 Княжа (natural=water, water=river)
        ↓ 3 node с Серемо: 220278932, 749439906, 952397092
relation 9617478 Серемо
```

Серемо **не** разделяет node с Селигером. Связь — через Княжу, и она читается по общим OSM-узлам, не по расстоянию.

**Варварина протока → Святое**

```
юг Селигера, outer way 49215825
  node 12188675959 (32.9294805, 57.2999152)
  node 12188675960 (32.9295327, 57.2999165)
        ↓ 2 node, 1 ребро
way 1316976066 Варварина протока (natural=water, water=river)
        ↓ 2 node: 12188675942, 12188675977
relation 18358803 Святое (outer way 28834878)
```

**Селижаровка** (сток на юге): relation **379295**, `type=waterway`. Way **28838371** (`role=main_stream`) начинается в node **247941768** (33.2768032, 57.0309341) на outer Селигера way **191300221**. Общих рёбер нет — как у осевой Полоновки, стык одним концевым узлом.

## Что рядом, но не «просто близко»: ложные кандидаты на «нет связи»

Если смотреть только на расстояние и имя, можно ошибочно записать в группу А:

| Объект | Почему не группа А |
|---|---|
| Святое 18358803 (~278 м до Селигера, 0 общих node с Селигером) | есть мост: Варварина протока делит node с обоими |
| Серемо 9617478 (~1117 м, 0 прямых node) | есть мост: Княжа |
| Гастовец way 81303076 (~28 м) | stream **81732492** имеет node Гастовца и node Селигера |
| Святица way 32486887 (~27 м) | river **1347279844** имеет node Святицы и node Селигера |

Близость 27–28 м сама по себе ничего не решает: у Садка 21 м и нет моста, у Святицы 27 м и мост есть. Различие — в общих `node id` цепочки.

## Наблюдения на этих примерах (не схема БД)

На исходных OSM-данных вокруг Селигера видно одно и то же различие:

1. **Есть физическая связь**, если водные геометрии разделяют `node id` (и часто целое ребро или даже целый way), либо существует промежуточный water/waterway, у которого есть общие node с обоими объектами.
2. **Нет физической связи**, если общих node и рёбер нет и нет такого промежуточного объекта — даже при 21 м между берегами.

Имя и расстояние эти два класса не разделяют.
